# GitHub Pages 운영

[Actions 기능별 안내](github-actions.md)에서 목적별 워크플로를 선택할 수 있습니다.

**접속 주소:** https://mtljm.github.io/investment-monitor/

- 공개 저장소 `main`에서 GitHub Actions로 생성한 시장 화면만 Pages에 게시합니다.
- 매일 한국시간 오전 7시 37분 목표로 대형주 20개와 지수·지표·ETF 23개를 수집합니다.
- 예약 실행은 지연·누락될 수 있습니다. 휴장일에는 최근 거래일 자료를 표시합니다.
- 휴대폰에서 주소를 열면 됩니다. 새로고침 자체는 수집 코드를 실행하지 않습니다.
- 수동 갱신: Actions → **01 시장 · 미국장 갱신** 또는 **01 시장 · 아시아장 갱신** → **Run workflow**.

표시 범위 20·50·100·200 메뉴는 유지합니다. 현재 배포에 없는 범위는 선택 불가하며, 해당 범위 JSON을 불러오면 사용할 수 있습니다.
기술적 분석 탭은 S&P 500·나스닥100·상위 20개만 다룹니다.

## 배포와 실패 처리

미국·아시아 예약 실행은 각각 독립 워크플로로 실행하며, `daily-pages.yml`은 화면 변경 배포와 선택 수동 업데이트를 담당합니다.

| 실행 | 처리 |
| --- | --- |
| 매일 07:37 KST 예약 | 미국만 수집 → 지표·비교 이력 계산 → 배포 |
| 평일 17:30 KST 예약 | 아시아만 수집 → 미국 자료·이력 유지 → 배포 |
| 화면 배포 수동 실행 기본값 `reuse` | 양쪽 게시 데이터 유지 후 화면만 배포 |
| 수동 실행에서 `us / asia / gurus / all` 선택 | 선택한 시장만 수집 후 배포 |
| HTML·CSS·화면 JS 수정 | 게시 데이터를 재사용해 화면만 배포 |
| 수집 설정·지표 계산 코드 수정 | 새 시세 수집 후 배포 |

화면 배포는 Pages의 `latest.json`에서 시장 데이터와 비교 이력을 함께 읽습니다. 같은 배포에서 만든 두 자료를 한 번에 가져와 시점 혼합을 방지합니다. 수집 시각·기술적 분석·전일 비교 신호·90일 이력은 유지하며, 비교 이력을 새로 계산하지 않습니다. 이전 형식은 `history.json`을 읽어 한 차례 이전하고, `latest.json`도 없으면 기존 `index.html` 내장 데이터로 복구합니다. 네트워크 오류나 데이터 버전 오류가 있으면 배포를 중단하며 자동으로 시세를 재수집하지 않습니다.

`latest.json`은 공개 시장 필드만 포함하는 버전 1 스냅샷입니다. 개인 계좌·보유량은 넣지 않습니다. 작업 전체를 같은 concurrency 그룹으로 직렬화해 화면 배포와 정기 수집의 충돌을 막습니다.

화면 소스는 `templates/dashboard.html`(구조), `dashboard.css`(스타일), `dashboard.js`(화면·공통 상세), `dashboard-safety.js`(갱신 상태·CSV), `market-temperature.js`(온도계), `sector-heatmap.js`(섹터 히트맵)로 나눕니다. `scripts/dashboard-template.mjs`가 배포 시 하나로 합치므로 다운로드한 HTML도 단독으로 열 수 있습니다.

수집에 실패하면 배포하지 않고 기존 사이트를 유지합니다. 화면의 수집 시각과 Actions 결과를 확인하세요.
일시적 네트워크·타임아웃·HTTP 408/425/429/5xx는 종목별 최대 3회 요청합니다. 요청당 제한은 8초, 재시도 간격은 1초·2초이며 병렬 작업 수 4개를 유지합니다. 서버가 2초보다 긴 Retry-After를 요구하면 조기 재요청하지 않고 해당 수집을 실패 처리합니다. 401/403/404·응답 형식 오류는 재시도하지 않습니다.

`config/**`와 `tests/**` 변경도 자동 배포 검사 대상입니다. `tests/*.test.mjs` 전체를 실행하므로 새 테스트 파일도 빠지지 않습니다. 테스트만 수정하면 기존 데이터 재사용, 실제 수집 설정·계산 코드 수정이면 새 시세 수집으로 진행합니다.
결과를 Git에 자동 커밋하지 않으므로 저장소의 `reports/latest.json`과 실제 사이트 수집 시각은 다를 수 있습니다.

## 비용과 공개 범위

공개 저장소의 표준 Linux 실행기와 무료 GitHub Pages만 사용합니다.
유료 실행기·캐시·외부 서버·추가 토큰은 사용하지 않고, 실행 시간 제한과 아티팩트 보관 1일을 적용합니다.
기존 예산 차단 설정을 유지합니다.

사이트에는 시장 데이터만 게시하지만 **저장소 코드와 커밋 이력도 공개**입니다.
보유 수량·계좌번호·토큰은 커밋하지 마세요. 인증정보는 GitHub Secrets로 관리합니다.
배포 권한은 deploy 작업의 `pages: write`, `id-token: write`로 제한합니다.

## 갱신 상태 확인

- 화면 상단에서 수집 시각과 미국 주식의 최근 마감 거래일을 별도로 확인합니다.
- 매일 07:37 KST 이후 새 수집이 없으면 08:15까지 갱신 대기, 이후에는 자동 갱신 지연으로 표시합니다. 주말·휴장일에도 수집 배치는 매일 실행되는 설정입니다.
- 미국 주식·지수·ETF의 최신 봉은 뉴욕시간 17:00 이후 해당 거래일까지 기대하며, 주말과 NYSE의 2026–2028년 정기 휴장일을 제외합니다. 임시 휴장일은 달력 업데이트가 필요합니다. 지원 연도 밖은 판단 불가로 표시합니다.
- 금리·환율·VIX는 서로 다른 거래 일정을 가지므로 4일 경과 경고를 유지합니다.
- 화면을 계속 열어 두어도 경고는 1분마다 다시 판단합니다. 시세 자체를 재수집하지는 않습니다.
- 지연 경고가 보이면 Actions의 마지막 실행 결과를 확인하고 필요하면 수동 갱신합니다.
- CSV의 음수 수익률은 숫자로 저장합니다. 텍스트의 수식 시작 문자만 보호하며 쉼표·따옴표·줄바꿈은 CSV 규칙으로 처리합니다.

휴장일 출처: https://www.nyse.com/markets/hours-calendars


## 시장별 배치

- 01 시장 · 미국장 갱신: `daily-us.yml`, 매일 07:37 KST (`37 22 * * *`). 미국만 수집하고 게시된 아시아 자료는 유지합니다.
- 01 시장 · 아시아장 갱신: `daily-asia.yml`, 평일 17:30 KST (`30 8 * * 1-5`). 아시아만 수집하고 미국 자료·수집 시각·비교 이력은 유지합니다. 각 시장 휴장일에는 최근 자료일 수 있습니다.
- 03 배포 · 화면 및 선택 데이터 갱신: `daily-pages.yml`에서 `us / asia / gurus / all / reuse`를 선택합니다. 기본 `reuse`는 시세 수집 없이 화면만 게시합니다. 기존 `refresh_data` 체크박스는 시장 선택으로 대체했습니다.
- 공통 게시 `publish-market.yml`의 단일 잠금으로 수집·최신 스냅샷 읽기·배포·공개 데이터 확인을 직렬화합니다. 실행 중 작업은 취소하지 않습니다. GitHub concurrency 특성상 대기 실행이 여러 개 쌓이면 이전 대기 실행이 대체될 수 있습니다.
- 시각 변경 시 `config/batch-schedules.json`과 두 워크플로 cron을 함께 수정합니다. 테스트가 두 설정의 일치를 검사합니다. GitHub 예약 실행은 지연·누락될 수 있으며 분리만으로 기존 예약 미생성 문제가 해결됐다고 볼 수는 없습니다.
